# 21 Viewer for VS Code

Opens PDF and `.scribe` documents inside VS Code in 21 Viewer, the viewer behind the 21 Viewer desktop and web apps: text selection and search, highlights and comments, page thumbnails and bookmarks.

## What it does

- A PDF clicked in the Explorer opens in the viewer. "Reopen Editor With..." offers the text editor instead, for any file.
- A document that changes on disk reloads at the same page, so a file regenerated by a build or a script refreshes in the open editor.
- Exports save through VS Code's save dialog, next to the document, which holds in a dev container or over SSH where a browser download would land on the wrong machine. Links in documents open in the system browser.
- The viewer follows VS Code's light, dark and high-contrast themes.
- Recognized text shows when the document or its `.scribe` session carries it, and OCR files (hOCR, ALTO, ABBYY) open alongside a document as its text layer.

## Limits

- No recognition inside VS Code: the extension ships without the OCR engine. Recognize in the desktop or web app and open the result here.
- Print does nothing inside VS Code: the webview sandbox blocks the print dialog. Export the PDF and print it from the system viewer.
- While the document has focus, the shortcuts the viewer handles itself (find, open) stay with the viewer.
- Not available in VS Code for the Web.
- The first open after an install takes a second or two while the viewer's workers and fonts load.

## Development

The extension lives in the scribe.js repository, beside the desktop shell. The page it shows is a build of the viewer, because a webview serves files to the page and not to its workers, so the workers must run from scripts the build makes self-contained.

- **Run from the checkout.** Run `npm run watch:vscode` at the repository root; it builds the page into `staging/` beside this file and keeps rebuilding on edits. Then start an Extension Development Host on this directory, for example `code --extensionDevelopmentPath=$PWD/scribe-ui/basic-viewer/vscode tests/test-assets` from the repository root, and any PDF in that folder opens in the viewer. A launch configuration that runs both steps under F5 can live in the repository's `.vscode/` folder, which git ignores. After an edit, wait for the build's "built in" line and run "Developer: Reload Webviews" in the host.
- **Package.** Run `npm install` in this directory once; it installs `vsce` and the VS Code types and writes the lockfile. `bash build.sh` then builds the viewer into `staging/`, copies the extension's files in and packages `dist/viewer-21-<version>.vsix`.
- **Install the package.** From a terminal in the window that should run it: `code --install-extension dist/viewer-21-<version>.vsix`, then reload the window. In a dev container the extension installs into the container, where the files are.
- **Smoke test.** `npm run smoke:vscode` at the repository root runs the staged page headlessly in Chromium the way a webview runs it: the viewer tree on one origin, the page on another with the extension's Content Security Policy, and a service worker that refuses every request a worker makes, as VS Code's does. It opens a fixture, checks the extracted text, the theme, a reload, the `.scribe` route, that no request was refused, and that a page drawn with a substitute font matches the worker-free viewer's drawing of it pixel for pixel. With `--cross-origin` it instead checks the library's other route for cross-origin workers, the one a CDN needs, without the service worker.

## How it works

The extension is a VS Code custom editor. VS Code hands it a document's URI; the editor's webview loads the viewer's modules and the document itself through VS Code's resource channel (`asWebviewUri`), which streams files from wherever the extension host runs. Nothing listens on a port. VS Code serves those files to the page only, never to a worker, so the page fetches each worker's script and starts the worker from a blob of its text; the build folds everything a worker would otherwise load, its late imports and the fonts it reads, into the script itself.
